# noteOS — APPROVED MVP-04: Native iPhone Prototype

**Lead Architect:** ChatGPT  
**Implementer:** Codex  
**Independent Reviewer:** Gemini (available again)  
**Status:** APPROVED — MVP-04 ONLY

## 0. Context

MVP-03.1 was accepted after Gemini Round 06.

MVP-01 through MVP-03 now provide:
- Canonical ProseMirror/Tiptap JSON v1.
- Local-first note storage.
- Checklist, tags, pin, search.
- Revision-safe autosave/recovery.
- Archive, Trash, Restore.
- Local audio recording/playback.
- Notes-only backup v1 and separate audio export.

MVP-04 introduces the first actual iPhone application.

## 1. Mission

Build a usable Expo/React Native iPhone prototype.

The target is a user who can create a note, edit supported content, organize it, record audio, close and reopen the app, and retrieve previously stored data without an internet connection.

Use the existing repository and accepted product contracts.

Do not build a web shortcut that merely loads the existing Next.js development server.

## 2. Preflight

Inspect:
- Repository architecture and AGENTS.md.
- Existing Expo/mobile experiments, if any.
- Canonical document engine and backup contract.
- Available macOS Xcode, iOS Simulator and attached iPhone tooling.
- Current supported Expo SDK and dependencies.

Create a dedicated mobile application within the existing monorepo.

Do not overwrite the Web application or change its database.

Prefer the simplest supported installation workflow.

For physical device builds, evaluate local Xcode Personal Team signing before paid Apple Developer/EAS services.

Never enter, request, store or upload the user's Apple credentials.

If a user action is required for code signing, Developer Mode, device trust or physical microphone access, report it explicitly and stop that blocked verification step.

## 3. Native Persistence

Prefer `expo-sqlite` for native notes metadata and canonical JSON.

Requirements:
- Stable note IDs.
- Creation/update timestamps.
- Revision and lifecycle.
- Pin and tags.
- Full canonical document JSON.
- Schema-aware read-only behavior.
- Transactional updates and conflict protection.
- Safe database initialization and upgrades.

Do not introduce a second incompatible canonical document format.

Share validation/business logic with the Web project where practical.

Never downgrade or silently rewrite unknown-schema documents.

No backend or Sync Engine is required for MVP-04.

## 4. Notes Experience

Implement a clean native interface:

- Notes Home.
- Create and open notes.
- Edit title.
- Edit supported body content.
- Checklist creation and toggling.
- Pin/unpin.
- Tags.
- Search and filtering.
- Archive, Trash and Restore.
- Safe delete confirmation.

Use native navigation and mobile-friendly input controls.

For rich-text editing, assess a locally bundled Tiptap editor through a controlled WebView bridge versus a deliberately limited native editor.

Prefer sharing the existing canonical document engine instead of reimplementing its schema.

Whichever approach is chosen:
- No remote editor webpage.
- No silent loss of formatting.
- Unsupported structures open read-only.
- Save/reload preserves exact supported JSON.
- Edits must not bypass revisions or discard drafts.

Document the choice and its actual limitations.

Do not build a full custom rich-text engine from scratch just for this prototype.

## 5. Native Audio

Use the Expo native audio APIs available in the installed SDK.

Implement:
- User-initiated microphone permission.
- Record, Stop and Save.
- Playback after reopening.
- Audio list under a note.
- Rename and delete.
- Export/share audio.
- Clear status on interruption and failed persistence.

Use persistent application document storage, not temporary cache as the only copy.

Store audio metadata in native SQLite.

Never mark a recording Complete until the native file has been finalized and verified accessible.

Treat metadata and file writes as separate operations with explicit recovery handling; do not claim they form one atomic SQLite transaction.

Preserve recoverable files where safe.

Do not implement background recording or lock-screen recording in this milestone.

Do not assume the Web's IndexedDB chunk model or Web Locks model applies natively.

## 6. Manual Interoperability With Web

Keep the existing `noteos.local-backup` v1 JSON contract.

Implement manual import/export of notes through the iOS Files/share workflow, where supported.

Test:
- Web backup imports into native storage.
- Metadata and checklist state survive.
- Native notes export in compatible canonical format.
- Web parser accepts the exported native backup.
- Duplicate IDs do not overwrite user data silently.
- Invalid/future documents are handled safely.

Do not imply audio is included in notes backup.

Native audio remains separately exported unless a future milestone explicitly approves a combined format.

This is manual file transfer, not synchronization.

## 7. Testing Gates

Gate A — Native notes:
- App starts.
- SQLite persists after restart.
- Notes can be created and reopened.
- Checklist state survives.
- Tags/pin persist.
- Future schema is read-only.
- Backup round-trip works.

Gate B — Native audio:
- Permission denial handled.
- Start/stop.
- Persist/playback.
- Interruptions and missing files handled.
- Export works.
- Delete confirmation.
- Existing notes stay intact.

Gate C — Actual iPhone:
- Install and open on a physical iPhone if authorized and available.
- Enter Vietnamese and Japanese text.
- Create, save, close and reopen notes.
- Test microphone with explicit user permission and synthetic speech.
- Play recording after app restart.
- Check offline operation after app bundle is installed.
- Capture device screenshots and diagnostics.

Automated simulator tests may supplement physical testing, but must never be reported as physical-device PASS.

If device access or signing is unavailable, finish the verifiable implementation and mark Gate C BLOCKED, not PASS.

Also rerun the existing Web regression suites if shared packages change.

## 8. Security, Privacy and Data Safety

No cloud AI, STT, analytics or external upload.

Do not transfer personal notes or microphone recordings into test artifacts.

Use synthetic fixtures.

Handle permission failures, app suspension and interrupted writes honestly.

Distinguish:
- Persisted successfully.
- Unsaved draft.
- Partial audio.
- Unknown recovery state.
- Actual data-loss case.

Do not silently clear app storage during development or upgrades.

## 9. UI Evidence

For native iOS use real device/simulator screenshots and diagnostics.

UI Lens remains for Web regression when needed; do not report Web viewport screenshots as iPhone-native evidence.

Capture:
- Home.
- Editor.
- Checklist.
- Tags.
- Recording.
- Playback.
- Import/export.
- Relevant error/recovery screens.

Prefer screenshots containing synthetic data.
