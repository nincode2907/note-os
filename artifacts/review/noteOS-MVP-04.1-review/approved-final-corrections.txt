## 1. Fix F-04.1-A — Explicit Discard Leaves Recovery Journal

File: `spikes/phase-00/gate1/mobile/App.tsx`

The current Unsaved Changes > Discard action calls `flushDraft()` but only deletes the recovery journal if `recoveryBaseRef.current !== null`.

That ref is null for an ordinary editing session that had no previously recovered draft.

Required behavior:
- Explicit Discard abandons the current unsaved changes.
- Cancel pending debounce writes.
- Settle or safely coordinate any in-flight recovery-journal write before deleting its matching journal.
- Delete only the journal belonging to the current note and expected revision.
- Do not delete another revision's journal.
- Do not recreate a discarded journal after navigation.
- If cleanup fails, show an error and do not falsely claim the draft was discarded.
- Save and Keep Editing must retain their existing behavior.

Add regression tests for:
1. Normal edit → Discard → reopen (no discarded draft).
2. Edit → pending journal write → Discard.
3. Stale recovery revision is not deleted.
4. Keep Editing retains unsaved changes.
5. Save clears the matching journal only after commit.

## 2. Fix F-04.1-B — Archived/Trashed Notes Remain Editable

Files: `App.tsx`, `store.ts`

The editor currently computes editability without checking note lifecycle.

Required:
- Only active schema-v1 notes with supported native content may edit title/body/checklist/tags through the body editor.
- Archived and trashed notes are read-only until restored.
- Display a clear Restore instruction.
- Enforce the restriction in `saveNote()` inside the SQLite transaction, not only the UI.
- Preserve allowed lifecycle transitions and future-schema data.
- Revision CAS must remain intact.

Add focused regression coverage for active/archived/trashed write policies.

Do not change the canonical schema or IndexedDB Web code.

## 3. Native Environment Compatibility Preflight

Important new finding:

The handoff host runs macOS 15.7.7.

Official Expo SDK 58 requirements list Xcode 26.4 or later.

Apple lists Xcode 26.4.1 as requiring macOS Tahoe 26.2 or later.

Before installing Xcode:

- Verify current macOS version and exact Mac hardware model.
- Check compatibility with a supported Tahoe version.
- Check available disk space and installation requirements.
- Check the actual supported Xcode version from Apple and Expo.
- Determine whether an OS upgrade is required.
- Inspect existing backup readiness without accessing private backup contents.
- Report a safe upgrade path and any blockers.

DO NOT automatically upgrade macOS, install a different Xcode release, run system-changing sudo commands, or change the selected developer directory without explicit user approval.

DO NOT downgrade Expo SDK 58 simply to fit an older Xcode.

If the host cannot meet the requirements, document alternatives and stop native validation as BLOCKED.
